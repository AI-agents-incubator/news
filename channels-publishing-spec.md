## 1. Архитектурная модель (реализовать до каналов)

### 1.1 Канонический контент-объект
Единый источник правды, из которого рендерятся per-platform варианты. Ориентировочная схема:

- `hook` — строка ≤175 симв. Несёт суть/CTA. Переживает обрезку ленты на всех площадках.
- `body` — основной текст.
- `long_text` — лонгрид (для площадок с длинным форматом).
- `media[]` — { type: image|video, url (публичный!), aspect, duration }.
- `links[]` — массив URL (важно для лимитов ссылок).
- `styling[]` — диапазоны форматирования (offset, length, styles) — для Threads-вложений.
- `overrides{}` — per-platform переопределения.

### 1.2 Слой нормализации формата
Реальная межканальная вариативность — **не язык, а формат**: аспект (9:16 / 1:1 / 4:5), лимиты длины, точка обрезки ленты, поддержка разметки, ссылочные лимиты. Слой нормализации превращает один канонический объект в валидный payload под каждую поверхность.

**Точки обрезки ленты (куда обязан попасть `hook`):**
| Канал | Обрезка «… ещё» |
|---|---|
| X | первая строка |
| Threads | ~175 симв `[VERIFIED]` |
| Instagram | ~125 симв `[VERIFIED]` |
| LinkedIn | ~140 симв / 3 строки `[VERIFY]` |
| Facebook | первый экран (~250–350) `[VERIFY]` |

### 1.3 Два тракта публикации — НЕ сливать в один код-путь
- **Sync (fire-and-forget, один вызов):** Telegram, X. Текстовые, без обработки медиа, без ревью. Дёргаются прямо из основного пайплайна.
- **Async (контейнер → загрузка → poll обработки → publish):** FB Page, Instagram, Threads, YouTube, LinkedIn(медиа), TikTok. Каждый пост — конечный автомат. Выносить в очередь с воркером и ретраями.

**Причина разделения:** зависший аплоад видео на медленном тракте не должен блокировать текстовый анонс, которому ничего не мешало улететь мгновенно.

### 1.4 Обязательная инфраструктура
- **Публичный media-хостинг (bucket/CDN):** Instagram и Threads делают cURL медиа по URL при создании контейнера — файлы должны лежать на публично доступном адресе на момент запроса.
- **Управление токенами:** у каждого провайдера свой жизненный цикл (см. §9).
- **Poll-механика:** у IG/Threads нет вебхука готовности медиа — статус контейнера опрашивается перед publish.

## 2. X (Twitter)

- **API:** v2. `[VERIFIED]` Модель pay-per-use с 6 февраля 2026 (подписочные тарифы для новых разработчиков отменены).
- **Auth:** OAuth 2.0 user-context (постим от имени аккаунта). Bearer — для app-only чтения. Кредиты покупаются в Developer Console, списываются по факту.
- **Стоимость `[VERIFY в консоли]`:** ~$0.015 за созданный пост; **$0.20 если в посте есть ссылка**; чтение ~$0.005. Кэшбэк до 20% в xAI-кредитах по порогам суммарного спенда.
- **Лимит символов:** 280 для базового аккаунта. **Аккаунт владельца — Premium**, поэтому посты через API наследуют длинный лимит (до ~25 000). Лонгрид публикуется одним постом без нарезки на тред. `[VERIFIED]` (Premium ≠ API-доступ — это разные счета; Premium даёт только форматный лимит.)
- **Rate limits `[VERIFY]`:** 15-мин скользящие окна (напр. ~3 500 чтений/15 мин на приложение); pay-per-use капнут на 2 млн чтений/мес.
- **Гейт:** нет. Ни аудита, ни App Review. **Самый быстрый в подъёме.**
- **Gotcha:** ссылку выносить в первый ответ-к-себе, не в тело поста — избегаем $0.20-сурчарджа и даунранка ссылок в UI.

## 3. Facebook Page — ✅ ПОДНЯТО (референс для консистентности)

- **API:** Graph API, `graph.facebook.com`, тек. версия `[VERIFY]` v25.0 (Meta версионирует ~2×/год, поддержка ~2 года).
- **Auth:** Page access token; права `pages_manage_posts` + `pages_read_engagement` + `pages_show_list`.
- **Контент:** текст, фото, видео, ссылки, Reels, Stories. Отложка через `scheduled_publish_time`.
- **Rate:** 4 800 × (engaged users) вызовов / 24 ч.
- **Примечание:** личный профиль и группы — API мёртв (профиль с 2018, `publish_to_groups` вырезан апрель 2024). Работает только Page. Уже реализовано — держать для единообразия обвязки.

## 4. Instagram

- **API:** Instagram Graph API (часть Meta Graph, `graph.facebook.com`). `[VERIFIED]` Basic Display API отключён 4 дек 2024 — только Graph.
- **Предусловия:** IG **Professional** (Business/Creator) аккаунт, привязанный к FB Page + Meta-приложение + права `instagram_content_publish` (+ `instagram_basic`). App Review для прод-доступа сверх 25 тест-юзеров.
- **Метод (двухшаговый, container model):**
  1. `POST /{ig-user-id}/media` — создать контейнер.
  2. `POST /{ig-user-id}/media_publish` — опубликовать.
  - Видео/Reels: resumable upload на `rupload.facebook.com`; **опрашивать статус обработки** (вебхука готовности нет).
- **Лимиты контента `[VERIFIED]`:**
  - Подпись: **2 200 симв** (не 2 000). Первые ~125 видны до «… ещё».
  - **Нет markdown** (bold/italic) в подписях.
  - Медиа — только по **публичному URL**.
  - Feed-видео 3–60 с; Reels до 90 с попадают в Reels-таб (API принимает до 15 мин, но в таб идёт только ≤90 с, 9:16).
  - Карусель до 10 (у части аккаунтов 20); все элементы кропаются под аспект первого.
- **Rate/publish `[VERIFIED]`:** 100 API-публикаций / 24 ч (карусель = 1); ~200 запросов/час/аккаунт общий.
- **Аспект:** 9:16 (1080×1920) или 4:5 (1080×1350).

## 5. Threads

- **API:** Threads API, `graph.threads.com` (v1.0). Отдельный от Graph, но та же Meta-платформа/OAuth. Привязан к IG-аккаунту.
- **Auth:** OAuth 2.0; App Review для прода. Токен ~60 дней. Бесплатно (платного тарифа нет).
- **Метод (двухшаговый):**
  1. `POST /{threads-user-id}/threads` (`media_type=TEXT`) — контейнер.
  2. `POST /{threads-user-id}/threads_publish` — публикация.
  - Медиа-контейнер должен завершить обработку до publish (**poll**, вебхука нет).
- **Лимиты контента `[VERIFIED]` (офиц. док обновлён 2 июля 2026):**
  - Основной `text`: **500 симв**.
  - **Текстовое вложение** `text_attachment.plaintext`: **до 10 000 симв** — подтверждено в API.
    - Стилизация: `text_with_styling_info` — диапазоны { `offset`, `length`, `styling_info`: Bold/Italic/Highlight/Underline/Strikethrough }, диапазоны не пересекать.
    - `link_attachment_url` — опциональная ссылка (покажется в ленте prominently).
  - **Итого один пост ≈ 10 500 симв программно.** Нарезка на само-реплаи под длинное **НЕ нужна.**
- **Ограничения вложения `[VERIFIED]`:**
  - Только к **текстовому** посту (не к посту с опросом).
  - **Ссылок ≤5** суммарно (уникальные URL в `text` + `link_attachment_url`). С 22 дек 2025 перебор → ошибка `THREADS_API__LINK_LIMIT_EXCEEDED` на шаге создания контейнера.
  - Если ссылка уже в основном `text` — вторую в вложение нельзя.
  - Контент вложения **не индексируется поисковиками и не федерируется** (SEO-канал мёртв, только внутри Threads).
- **Rate `[VERIFIED]`:** 250 API-публикаций / 24 ч, 1 000 реплаев, 100 удалений на профиль. Формула 4 800 × impressions.
- **Медиа:** видео mp4/mov ≤1 ГБ, 0–5 мин; карусель до 10.
- **Форматное правило:** `hook` ≤175 в `text`, лонгрид со стилями — в `text_attachment.plaintext`.

**Референс-скелет payload (создание контейнера с вложением):**
```
POST https://graph.threads.com/v1.0/{THREADS_USER_ID}/threads
  media_type=TEXT
  text=<HOOK ≤500>
  text_attachment={
    "plaintext": "<до 10000 симв>",
    "link_attachment_url": "<источник, опц.>",
    "text_with_styling_info": [
      {"offset":0,"length":7,"styling_info":["bold","italic"]}
    ]
  }
→ вернёт {id: CONTAINER_ID}
POST /{THREADS_USER_ID}/threads_publish  creation_id=CONTAINER_ID
```

## 6. LinkedIn

- **API:** Posts API (часть Community Management API), REST `/rest/posts`. OAuth 2.0 (authorization code).
- **Заголовок:** каждый запрос требует `LinkedIn-Version` в формате `YYYYMM`.
- **Два пути:**
  - **Личный профиль:** продукт «Share on LinkedIn», scope `w_member_social`. Легко. ~100 вызовов/день/участник.
  - **Страница организации (ALEXTANIA25):** scope `w_organization_social`. `[VERIFIED]` Community Management API — только для зарегистрированных юрлиц, через access-request + веттинг (Development tier → заявка на Standard). Нужны: верифицированный бизнес-email, легальное имя/адрес/сайт/privacy policy, подтверждение super-admin Страницы.
- **Токены:** access 60 дней, refresh 365 дней.
- **Контент:** текст до **3 000 симв**; изображения, статьи, видео, карусели, документы.
- **Ограничения `[VERIFY]`:** нативного планировщика в API нет (расписание держать у себя); @-меншены в тексте поста через API не поддерживаются; опросы через API — под вопросом.

## 7. YouTube (если гонится видео)

- **API:** Data API v3. Метод `videos.insert` (resumable upload, чанки кратно 256 КБ). OAuth 2.0, scope `youtube.upload`. **Verified GCP project** для публичных видео.
- **Квота `[VERIFY — конфликт источников!]`:** 10 000 units/день/проект по умолчанию. Исторически загрузка = 1 600 units (~6 видео/день). Есть сообщения о снижении до ~100 units (дек 2025) и выносе в отдельный суточный бакет (июнь 2026) — **агент обязан сверить с офиц. страницей квот**, цифра нестабильна. Чтение = 1 unit, поиск = 100 units.
- **Shorts:** тот же endpoint; вертикаль 9:16, ≤60 с, `#Shorts` в заголовке.
- **Увеличение квоты:** бесплатно по Audit and Quota Extension Form (ревью недели-месяцы).
- **Объём владельца (1 длинное/день) — тривиален** при любой трактовке квоты.
- **Три API:** Data / Analytics / Reporting (управлять как отдельными системами).

## 8. TikTok (опционально, позже)

- **API:** Content Posting API. Два режима:
  - `video.upload` → черновик/inbox (креатор дописывает в приложении). Доступ проще, но убивает автоматизацию.
  - **Direct Post** (`video.publish`) → сразу в паблик. **Требует аудита** сверх регистрации приложения.
- **Аудит `[VERIFIED]`:** 2–4 недели, несколько раундов. UX-требования: перед постом показывать username + avatar креатора (TikTok проверяет).
- **До аудита:** ≤5 юзеров/24 ч, только `SELF_ONLY` (приватно), аккаунт должен быть private на момент постинга.
- **Токены:** 24 ч. **Rate:** publish ~6 запросов/мин на user-токен; `creator_info` query 20/мин.
- **Flow:** `POST /v2/post/publish/creator_info/query/` (privacy options, max duration) → init → upload → publish. **Edit-эндпоинта нет** (правка = удалить + перезалить).

## 9. Подкаст (опциональный столб)

- **Архитектура — RSS.** Публикуешь в **один хост** → хост генерит RSS → директории (Apple, Spotify, Amazon Music, Pocket Casts, YouTube Music, **Яндекс Музыка** и др.) **сами вычитывают** фид. У директорий **нет upload API и он не нужен.** Фид подаётся в каждую директорию **один раз** при запуске.
- **Apple Podcasts:** первую подачу фида — руками через Podcasts Connect. Дальше поток идёт сам.
- **Хост с лучшим API — Transistor:** REST, ресурсы Shows/Episodes/Analytics/Webhooks. Загрузка аудио: запросить authorized upload (`upload_url` + `content_type`) → PUT MP3 → создать эпизод. Rate 10 запросов/10 с. Вебхуки. Flat-rate, безлимит шоу/эпизодов.

## 10. Сквозные требования (реализовать в обвязке)

### Жизненные циклы токенов
| Канал | Токен | Обновление |
|---|---|---|
| X | кредиты (без срока) | пополнение баланса |
| FB Page / IG / Threads | long-lived ~60 дней | refresh flow |
| LinkedIn | access 60 дн | refresh 365 дн |
| TikTok | 24 ч | refresh |
| YouTube | OAuth | refresh-токен (хранить безопасно) |

### Обработка ошибок / ретраи
- 429/401/400 → exponential backoff (1s, 2s, 4s…), не бёрстить.
- Async-тракт: FSM на пост — `container_created → media_uploaded → processing → published`; ретраи на каждом переходе.
- Threads: перехватывать `THREADS_API__LINK_LIMIT_EXCEEDED` (≤5 ссылок).

### Meta App Review — рычаг
Одно Meta-приложение покрывает **FB Page + Instagram + Threads** (подать ревью на каждый scope). ~80% обвязки (OAuth, токен-модель, container/publish) переиспользуется. Это главная экономия усилий.

### n8n mapping
- Sync-тракт (Telegram, X) → HTTP-ноды прямо в основном флоу.
- Async-тракт (Meta, YouTube, LinkedIn-медиа, TikTok) → очередь + воркер, разные ветки ретраев.
